## 1. Why this topic, and what is settled

- **Commutation is proved by comparing `q`-coefficients.** The pin's
  function-level files do not manipulate the double coset; they show
  `qCoeff (T_p (T_q f)) n = qCoeff (T_q (T_p f)) n` from T5's
  `coeffHeckeT_comm`/`coeffHeckeU_comm`/`coeffHeckeT_coeffHeckeU_comm`, then close
  with `UpperHalfPlane.eq_of_forall_qCoeff_eq` (T5). The `S_` file imports T5's
  `UpperHalfPlane.qCoeff_heckeU/T` and SET 2's `mdifferentiable_*`/
  `isBoundedAtImInfty_*`/`periodic_*` for the side conditions of that uniqueness
  lemma. So T7 is a **consumer** of T5 + T3, with no new analytic content.
- **The bundled commutations reduce to the function-level ones.** The pin's
  13-line `CuspForm.heckeTLin_comm` is `by_cases p = q` (`Commute.refl`), then
  `rw [commute_iff_eq]; ext f τ; simpa using congrFun
  (ModularFormClass.heckeT_heckeT_comm f (by simp) (Nat.coprime_primes hp hq).mpr hpq) τ`.
  The other three have the same shape.
- **The `LaurentSeries` family is independent.** `LaurentSeries.heckeU`/`heckeV`/
  `heckeT` are the formal-series operators of the survey §11; their five
  commutation lemmas are `20`-line files that reduce to the coefficient algebra
  on `LaurentSeries`, not to the modular-forms side. Port the two definition
  modules and the five lemmas together; nothing else in SET 3 needs them, so this
  is the one self-contained corner.
- **The algebra is thin once the commutations exist.** `heckeGenerators` is the
  union of the `T_ℓ` (`ℓ ∉ S`, `ℓ ∤ N`) and the `U_q` (`q ∣ N`, `q ∉ S`);
  `heckeAlgebra = Algebra.adjoin ℤ heckeGenerators`; `commute_of_mem_heckeGenerators`
  is a four-case dispatch onto the three `CuspForm` commutation theorems; and
  `instIsMulCommutative` is `Algebra.isMulCommutative_adjoin`. `instCommRing` and
  `instIsAddTorsionFree` follow from it and the `ℂ`-torsion-freeness of `End`.
- **This is the survey's Stage C endpoint.** With it, the port has the operator,
  its invariance, its analytic/coefficient theory, its bundling, and its algebra —
  the surface SET 4's eigenform interface and the Taylor–Wiles consumers need.

**Settled: defer the finite/free algebra.** `CuspForm.moduleFinite_heckeAlgebra`,
`HasIntegralStructure.moduleFinite/Free_heckeAlgebra`,
`mem_intLattice_of_mem_heckeAlgebra`, `span_heckeTLin_eigen_eq_top`,
`finrank_span_heckeAlgebra_eq_finrank`, `heckeEvalForms_range_eq_top` and the
`intLattice` machinery are the survey §9 *finiteness* half; they need the integral
lattice and are SET 4. Port only the 14 declarations of
`Def_CuspForm_HeckeAlgebra.lean` here.

**Settled: the `LaurentSeries` placement.** The pin's two definition modules are
`Definitions/` files; the port's `ModularCurve/Defs/` holds the `qExpand`/`qTwist`
series vocabulary, so the formal Hecke operators live there (`LaurentSeriesHecke.lean`),
not under `ModularForms/`.

The key statements:

```lean
theorem ModularFormClass.heckeT_heckeT_comm {F : Type*} [FunLike F UpperHalfPlane ℂ]
    {Γ : Subgroup (Matrix.GeneralLinearGroup (Fin 2) ℝ)} {k : ℤ} [ModularFormClass F Γ k]
    (f : F) (hΓ : (1 : ℝ) ∈ Γ.strictPeriods) {p q : ℕ} (hpq : Nat.Coprime p q) :
    ModularForm.heckeT k p (ModularForm.heckeT k q ⇑f) =
      ModularForm.heckeT k q (ModularForm.heckeT k p ⇑f)
theorem CuspForm.heckeTLin_comm {N : ℕ} (k : ℤ) {p q : ℕ} (hp : p.Prime) (hpN : ¬ p ∣ N)
    (hq : q.Prime) (hqN : ¬ q ∣ N) :
    Commute (CuspForm.heckeTLin k hp hpN) (CuspForm.heckeTLin k hq hqN)
def CuspForm.heckeGenerators : Set (Module.End ℂ (CuspForm (CongruenceSubgroup.Gamma0 N) k)) :=
  {T | ∃ (ℓ : ℕ) (hℓ : ℓ.Prime) (hℓN : ¬ ℓ ∣ N), ℓ ∉ S ∧ T = heckeTLin k hℓ hℓN} ∪
    {U | ∃ (q : ℕ) (hqN : q ∣ N), q.Prime ∧ q ∉ S ∧ U = heckeULin k hqN}
def CuspForm.heckeAlgebra : Subalgebra ℤ (Module.End ℂ (CuspForm (CongruenceSubgroup.Gamma0 N) k)) :=
  Algebra.adjoin ℤ (heckeGenerators N k S)
instance CuspForm.heckeAlgebra.instIsMulCommutative : IsMulCommutative (heckeAlgebra N k S)
```

## 3. What is different about this topic

- **The first topic that consumes T5's uniqueness lemma.** The function-level
  commutations are the reason T5 ports `UpperHalfPlane.eq_of_forall_qCoeff_eq`;
  if T5 left it out, T7 must not copy it — send it back to T5's module.
- **The commutation statements are coprime-only.** The non-coprime product
  relation `T_m T_n = T_{mn}` is not in the pin (survey §7's gap); do not add it.
- **The algebra is small but its instances are load-bearing.** `heckeAlgebra`'s
  `CommRing`/`IsMulCommutative` instances are what the Taylor–Wiles consumers
  need; check the instance *names* match the pin's (`heckeAlgebra.instIsMulCommutative`
  etc.), because downstream code refers to them.
- **No integral lattice.** `heckeAlgebra` is over `ℤ` but the module is
  `CuspForm … k` over `ℂ`; the lattice/finiteness layer is SET 4.

## 4. Budget

**2–3 goal rounds, checkpoint at 2.** Round 1: the `LaurentSeries` defs + the five
formal commutations (self-contained). Round 2: the function-level and bundled
commutations. Round 3: the algebra and bookkeeping. The only real risk is the
function-level files' local side-condition block — the work order's verdict is
"import T5, do not copy", and if that fails, the finding is that T5's uniqueness
lemma needs a side-condition API.

**Stop early on**: a function-level commutation needing a helper that is not in
T5 (report it and stop — do not open the algebra); a bundled commutation whose
binder differs from its wrapper; or the algebra's instances failing to synthesize
without a new typeclass instance (the `IsMulCommutative` route is
`Algebra.isMulCommutative_adjoin`, already used by the pin).
